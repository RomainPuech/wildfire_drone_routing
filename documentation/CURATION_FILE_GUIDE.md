# WFDroneBench curation file guide

This document explains how each curation file was used to construct
WFDroneBench, with particular attention to `historical_match` and
`scenario_summary.csv`.

The raw fire-spread simulations came from Sim2Real-Fire. Our curation did not
rerun the physical simulators: it selected scenarios, associated them with
historical ignitions, aligned risk products, converted file formats, and
generated metadata.

## Pipeline overview

```text
Sim2Real-Fire layout folders
        │
        ├── layout-size filtering (30 m grid; width >= 500 cells)
        │
FPA-FOD + newer USFS ignition records
        │
        ├── space-only matching
        │      └── selected_scenarios.txt
        │
        ├── space-and-date matching
        │      └── selected_scenarios_historical.txt
        │
        ├── JPG mask conversion and empirical burn maps
        │      ├── scenarii/<scenario>.npy
        │      ├── burn_map.npy
        │      └── burn_map_noncumulative.npy
        │
USFS BP/WHP continental rasters
        │
        ├── exact-grid alignment
        │      ├── static_risk_bp2024.npy
        │      └── static_risk_whp.npy
        │
        └── scenario metadata
               └── scenario_summary.csv
```

## Supported reviewer-facing files

These files under `code/dataset_curation/` are the supported, non-destructive
implementation.

### `code/curate_dataset.py`

Repository-root launcher. It exposes the curation commands without requiring
the package to be installed.

### `code/dataset_curation/__main__.py`

Defines the command-line interface:

- `footprints`: inventory and filter Sim2Real layout grids;
- `merge-fires`: normalize and deduplicate FPA-FOD and newer USFS records;
- `select`: run space-only or date-aware fire-to-scenario matching;
- `risk`: align a continental BP or WHP raster to every layout grid;
- `preprocess`: convert selected JPG masks and compute empirical burn maps;
- `summary`: generate `scenario_summary.csv`.

See [`code/dataset_curation/README.md`](../code/dataset_curation/README.md) for
the complete command sequence.

### `code/dataset_curation/geospatial.py`

Handles operations that require real map coordinates:

1. Reads `Vegetation_Map/Existing_Vegetation_Cover.tif` as the authoritative
   layout grid, CRS, affine transform, height, width, and 30 m resolution.
2. Excludes layouts narrower than 500 columns by default.
3. Merges the FPA-FOD 2022 records with the newer USFS occurrence export.
4. Deduplicates records with identical latitude, longitude, and discovery
   timestamp.
5. Reprojects BP/WHP values onto the exact destination grid instead of merely
   resizing arrays.

### `code/dataset_curation/matching.py`

Contains grid-coordinate matching.

- A simulated scenario cannot be assigned to more than one historical fire
  within a layout.
- Space-only matching uses a maximum Chebyshev distance of 5 cells.
- Date-aware matching uses a maximum Chebyshev distance of 10 cells and a
  maximum date difference of one day.
- Stable tie-breaking makes results independent of filesystem ordering.

### `code/dataset_curation/workflow.py`

Connects geospatial records, scenario masks, matching, and metadata.

- Projects each historical ignition into the corresponding layout grid.
- Builds the scenario ignition index from the first fire-mask frame.
- Writes auditable selection manifests containing matched and unmatched fires,
  coordinates, distances, dates, and layout acceptance.
- Uses the space-only manifest to define the curated scenario corpus.
- Uses the date-aware manifest to set `historical_match`.
- Generates `scenario_summary.csv`.

### `code/dataset_curation/preprocess.py`

Performs canonical mask processing:

- natural numeric frame ordering;
- grayscale conversion and division by 255;
- binary thresholding at `>= 0.5`;
- `float32` `T x N x M` NPY output;
- cumulative and noncumulative empirical burn-map calculation;
- optional temporal offsets from the tracked `config_s2r.json`.

`config_s2r.json` Was generated by sampling offsets uniformly at random for each scenario.

## Intermediate selection files

### `selected_scenarios.txt`

Defines the main curated corpus. Each valid line maps a selected scenario ID to
the recorded-fire ID assigned during the space-only pass:

```text
0016_00042, 123456
```

The historical pass matched each recorded ignition to an unused scenario
within 5 cells using the closest available ignition location. Calendar day was
not required. Layouts with more than 20% unmatched eligible fires were
rejected.

### `selected_scenarios_historical.txt`

Defines the scenarios marked `historical_match=True`. The second pass used
newer USFS records from 2019 onward and required:

- a scenario ignition within 10 cells of the recorded ignition;
- a scenario weather date within one day of the recorded discovery date;
- no reuse of a scenario within the layout.

This file is a classification manifest. It is separate from the space-only
file that defines the full corpus.

## How `scenario_summary.csv` was generated

The historical file contains one row per scenario retained by
`selected_scenarios.txt`. Its fields were:

- `layout_number`: four-digit layout identifier;
- `scenario_number`: scenario identifier within the layout;
- `season_number`: winter, spring, summer, or autumn encoded as 1--4;
- `seasonal_match`: whether the associated recorded fire and simulated
  scenario have the same month and day;
- `historical_match`: membership in
  `selected_scenarios_historical.txt`;
- `big_fire` / `small_fire`: classification from final-frame fire radius;
- `fast_fire` / `slow_fire`: `fast_fire=True` when burned cells at frame 10
  are at least 50% of final burned cells.

The original generator loaded both FPA sources again to recover the discovery
date associated with each `selected_scenarios.txt` fire ID. It then loaded each
selected trajectory, computed these fields, accumulated the rows in a Pandas
DataFrame, and wrote `scenario_summary.csv`.
